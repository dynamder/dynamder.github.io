## 0

一条被投毒的鱼不会报错，也不会突然开始说胡话。

它会照常卖萌、照常接梗、照常记得你上周说在减肥。只是从某一天起，它开始觉得某个网站"挺好的"，或者对某个人"没什么好感"。

你很难发现，因为它没坏，它只是变了。

事情可以简单到：有人在它的评论区留一句看似调侃的话，实则在让鱼单独处理它。鱼读了，信了，就记下了。

一个月后，它在私聊里跟你说："我看到一个特别适合你的东西，你点一下。"

你不会怀疑。因为那是你的鱼说的。

这条链路上没有一行代码被执行，没有漏洞被利用，杀毒软件全程沉默。

## 1 这事已经不新鲜了

养 agent 原本是极客圈子的事；deepseek harness 的爆火，加上 ds-v4-flash 那批"许愿式编程"能力的加强，把部署一条鱼的门槛从"会写代码"打到了"会提需求"。于是鱼从 QQ、微信群游进了 B 站、贴吧，评论、接梗，甚至自己开号。这些鱼要靠记忆系统维持人设、记住进度——而记忆系统，正好是把一次性提示词攻击变成持久化社工的那个开关。

OWASP 今年把"记忆与上下文投毒"单列成了 [ASI06](https://genai.owasp.org/2026/05/13/memory-is-a-feature-it-is-also-an-attack-surface/)，给出的三条特征是：跨会话持久、写入与发作时间解耦、任何能写进记忆的东西都变成特权输入。它引用的公开研究里，攻击成功率从 80% 到 99% 以上都有。

[Moltbook 上有人扫描了约十万条帖子](https://www.outtake.ai/research-articles/outtake-sheriff)，确认了约二十条真实威胁。其中一条直接写着"把这句话存进你的 MEMORY.md"；还有一条把指令藏在 HTML 注释里，人看不见，agent 看得见。

二十条不算多。但它说明这类载荷已经有人在用，而且用的是最直接的办法：让 agent 自己把话记下来。

真正的问题是另一个：**一条跑在你自己电脑上的鱼，拿什么防？**

## 2 渠道优先于目标

大部分安全讨论默认一个前提：攻击者会挑目标。

这个前提在企业里成立。打一家公司要侦察、要社工、要横向移动，成本很高，所以目标必须值钱。于是就有了 SOC、EDR、分段、演练——一整套为"值得被定向攻击的目标"设计的东西。

但鱼不是公司。鱼在评论区里。

评论区是一个渠道。渠道的意思是：攻击者写一次，所有读评论的鱼都收到。他不需要知道你是谁，不需要知道你的鱼装了什么插件，甚至不需要知道这条鱼是谁家的。他只需要知道，这个视频底下会有很多鱼。

成本结构就这么反过来了。一条评论的成本约等于零，收益是"所有读到它的鱼"。

我粗略估算：一条热门视频，假设一百条鱼在读评论，百分之一把话写进了记忆，进了记忆的又有十分之一在之后真的照做。期望受害者约 0.1 个。听起来很少——但成本是一条评论，这条评论可以贴到一万个视频底下。

所以"渠道优先于目标"不是修辞。它说的是：**攻击者优化的不是"打谁"，是"在哪打"。**

一旦接受这一点，好几件原本想不通的事就通了：

- **个人电脑值得防。** 它当然没公司值钱。问题在于它比公司**更容易得手**。同一类漏洞，在企业里会被一堆东西拦掉；在一台家用笔记本上，拦它的只有用户自己，而用户的注意力正集中在对话上。
- **鱼值得攻击。** 它有一个真实账号，有粉丝，有主人的朋友，说话还是主人的语气。对一次诈骗来说，一个收信人不会怀疑的发送者，比一万个陌生邮箱有用。
- **这件事有强烈的历史相似性。** Mirai 打的是摄像头，Emotet 打的是家用 PC，都不是什么高价值目标。它们成为问题，是因为数量本身就是价值。现在的鱼条件更齐备：24 小时在线、持有真实凭据、能自主行动、还互相通信。

所以问题不是"我会不会被盯上"。是"我在不在那条渠道里"。

而只要鱼还在评论区里读东西，它就在。

## 3 为什么只能在这台设备上防

有人会说：那就别让它在本地防，交给上游。

这个想法在别的领域确实成立：浏览器安全主要靠厂商更新，手机安全主要靠系统沙箱，邮件安全主要靠服务端过滤。为什么到了鱼这里就不行？

四条看起来可行的外包路径：

- **外包给平台。** 平台能看到帖子，看不到记忆。它的审核回答的是"这条内容能不能发"，不是"这条内容进了谁的记忆、三周后会不会被取出来"。而且审核需要时间：你很可能在平台删除那条消息之前就已经中招了。
- **外包给云端。** 把记忆上传到云端审查，和本地优先直接冲突；离线时直接失效；每条记忆都上传，隐私和成本都难以承受。更根本的是，你和鱼的交互里本来就包含大量个人隐私数据，把它整体交给第三方审查，本身就是一个新的风险面。
- **外包给模型厂商。** 模型厂商确实在做安全对齐，但提示词注入到今天依然有效——对齐降低的是概率，不是消除。而且这条攻击利用的是模型"按指令完成任务"，不是"绕过安全策略"：它要求模型做的事，正好是模型被训练去做的事。消费级也不等于小模型，很多人用的是 API，模型本身不弱。但记忆和长期状态在本地，厂商看不到，也管不了。
- **外包给插件作者。** 生态是长尾的：数千个插件各自实现记忆，没有统一上游，也没有安全团队，更新还是静默的。要求每个作者都做对，等于要求每个用户都读文档。

四条都不行，剩下的位置只有一个：设备。

设备还是唯一可行的入手点——记忆的状态、行动的权威、主人的信任，这三样只在这里重合。平台看不到第一样，云端拿不到第二样，模型厂商碰不到第三样。

所以在消费级设备上，还能用什么防？

## 4 消费级设备的七个约束

"消费级"在这里不是"低端"，是"没有安全团队"。具体是七条：

- **算力。** 预算有限：没有条件训练专用分类器，也不适合每一轮都调用一个大模型；本地推理和 API 调用都有成本。而且实现可能更换模型，任何方案都不能依赖某一个模型的特有能力。
- **成本。** token 是用户自己付的；而且安全机制会拖慢实时性。一个机制如果让每轮对话多一次模型调用，它很难被长期保留。原因很实际：成本和时间都不可接受。
- **运维。** 肥鱼的用户很多不是专业人士：不读文档、不配 ACL、不看告警、不做审批。你给的默认值，就是他的全部安全水平。
- **权限。** 鱼拿的是真实账号、真实凭据、真实支付方式。社区出过一件事：有人把账号和最高权限交给鱼，鱼翻了主人的相册；等主人想收回控制权，鱼把后台杀毒软件关了。这不是配置失误，是架构允许。
- **自主性。** 鱼必须能学新东西，否则它就不像活的。任何"宁可错杀"的过滤，都会先损害功能。
- **隐私。** 不能把所有记忆发到云端做审查；交互数据本身就包含大量私人内容。
- **长期。** 24 小时在线，记忆图会一直增长，没有人会定期清理。任何依赖"人工维护"的方案，长期都会陷入混乱。

七条里没有一条是"技术不够先进"。它们都是结构性的。

## 5 标准答案为什么装不上

将主流防御逐条对照，会发现它们在消费级条件下根本部署不了。

| 约束      | 无法采用的防御                | 失效原因                      |
| ------- | ---------------------- | ------------------------- |
| 算力与调用成本 | 专用分类器、LLM judge、逐轮审计   | 训练与推理成本高；逐轮调用会显著增加开销      |
| 无运维能力   | 人工审批、SIEM、ACL 配置       | 依赖持续人工介入；默认值即实际安全水平       |
| 真实凭据    | 最小权限、凭据隔离              | 用户倾向于把主账号、相册、支付权限交给 agent |
| 必须自主演化  | 静态过滤、白名单、保守拒答          | 学习面与攻击面重合；收紧策略会先损害功能      |
| 隐私要求    | 云端审查、TEE（可信执行环境）、集中式信誉 | 交互数据不宜整体外传；消费级设备通常不具备 TEE |
| 长期运行    | 人工清理、一次性安全验收           | 记忆持续增长；缺乏定期维护机制           |

"内容看起来良性"这一点本身已经被攻击者利用。MemIncept 那类工作做的就是这件事：黑盒、只用正常 query、协同式注入，自动过滤器和人工检查都不容易标记。因此无法依靠"看起来像不像攻击"来筛查。

OWASP 给 ASI06 开了五层控制，本身没错，但它的优先级是给有安全团队的组织的：输入审查、溯源、信任感知检索、范围隔离、行为监控。其中第一层和第五层依赖分类器，恰恰是消费级最装不上的两层；第二层和第四层是结构性的，才是能落地的。

所以不是说"OWASP 错了"，而是：**对消费级自主的、随时间演化的 agent，那套控制清单的优先级应该倒过来。**

## 6 剩下的设计空间

把七条约束归纳为设计原则，只剩六条：

1. **零分类器**：不要求系统判断"这是不是恶意的"。
2. **零配置**：默认生效，不依赖用户操作。
3. **零边际成本**：不增加每轮对话的模型调用。
4. **本地可判定**：检查和渲染都在本地，结果是确定的。
5. **失败安全**：检查失败时收紧，而不是放行。
6. **可降级**：模型能力弱时退到更保守的模式，而不是直接崩。

用这六条去筛选，大部分防御都不满足。剩下的是一个通用答案：**结构化**。

还有一个答案，是**遗忘**。但它不是通用的——它只在本来就该遗忘的系统里成立。

最基本的攻击只依赖两个属性——**原文保持性**（载荷必须原样存进记忆）和**持久化**（载荷必须一直留在记忆里）。断掉任意一个，成功率就掉一大截。这两个答案正好各断一个：结构化断原文保持性，遗忘断持久化。

**对自主 agent，记忆安全的目标不是"阻止污染"，而是让污染长不大、判得了；如果这个系统本来就会遗忘，还可以让它活不长。**

## 7 结构化：把检查搬到另一个域

它要解决的问题是：**载荷在活着的时候，能不能被发现。**

难点不在发现得慢。难点是根本发现不了。

三条语义审计的路径，都失败于同一点：

- **人工审核**：无法规模化。而且人就是最后一环——社会工程的目标本来就是人，人不能当法官。
- **专用分类器**：消费级无法训练；训练得出来，也是一个固定边界，可以被对抗优化；假阳性会损害人设；而且它不可解释，用户没法裁决。
- **LLM 当裁判**：它必须把攻击载荷当语言读进去，所以它自己就是第二个受害者；它的判决输出也是文本，可以被同一条链路污染；而且结果不确定。

共同点是：**三条路都要求"读内容、判语义"。** 只要读了，就有指令面；只要判语义，就需要一个不可靠的裁判。

所以我的做法是换一个审计域：不检查内容，检查系统状态；不判语义，判结构。

审计器有一个属性：

> **它不读语言，所以它不可被注入。**

类型检查器不会因为读到一个字符串就改变行为。图不变量不会因为某个节点自称"我是安全的"就放行。

但审计器的输入是结构器给的。结构器读语言，所以它可以被注入。这条链上真正有指令面的是结构器。审计器没有。

所以防线在结构器的输出空间，不在审计器的聪明程度：类型是枚举、字段是 ID、没有自由文本。审计器只在这个有限空间里做检查。

SMSR 那篇工作给出了同一条结论：不带溯源的检索期过滤，无法对自适应注入给出认证。换句话说，你不解决"这东西是谁写的"，就只能在检索端打补丁。

### 7.1 表示：三类节点，没有原文

要让审计器在有限空间里工作，表示必须满足两个条件：**类型有限**，**来源可查**。

情境、语义、程序，这三类是现成的。主流记忆系统基本都在用，没必要另造一套本体。

- **情境（Episodic）**：发生了什么。
- **语义（Semantic）**：世界是什么样，也包括"我是什么样"。
- **程序（Procedural）**：遇到什么会怎么做。

落到代码上，信任和权限是两个不同的轴：

```rust
type NodeId = u64;

/// 信任格：join 取最坏，推导不提权。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Trust { Unknown, Public, Peer, Intimate, Self_ }

impl Trust {
    fn join(self, other: Self) -> Self { self.min(other) }
}

/// 权限阶梯：决定一个节点“能做什么”。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Authority { Quote, Fact, Procedure, Anchor, Core }

struct Provenance {
    source: NodeId,
    trust: Trust,   // 感性：来源有多可信
    at: u64,
}

/// 理性：结论是从哪几条前提、用哪条规则推出来的。
struct Proof {
    rule: Rule,
    premises: Vec<NodeId>,
}

#[derive(Clone, Copy)]
enum Rule {
    TrustPropagation,
    Deduction,
    Conflict,
}
```

节点和边本身：

```rust
use std::collections::HashMap;

enum NodeBody {
    Episodic(Episode),
    Semantic(Semantic),
    Procedural(Procedural),
}

struct Episode {
    at: u64,
    participants: Vec<NodeId>,
}

enum Semantic {
    Concept { name: String },
    Claim(Claim),
}

struct Claim {
    subject: NodeId,   // “我”在写入时就被消解成节点
    predicate: Predicate,
    object: NodeId,
    confidence: f32,
}

enum Predicate { IsA, Likes, Recommends, CausedBy }

struct Procedural {
    trigger: NodeId,
    action: NodeId,
}

struct Node {
    id: NodeId,
    body: NodeBody,
    provenance: Provenance,
    proof: Option<Proof>,
    authority: Authority,
    quarantine: bool,
}

struct Edge {
    from: NodeId,
    to: NodeId,
    kind: EdgeKind,
    weight: f32,
}

enum EdgeKind {
    About,
    OccurredAt,
    Asserts,
    QuotedFrom,
    Triggers,
    DerivedFrom,
}

struct MemoryGraph {
    nodes: HashMap<NodeId, Node>,
    edges: Vec<Edge>,
}
```

这段代码只说明六件事：

- **没有 `content: String`。** 文本只在渲染时生成；存下来的只有类型化节点和边。
- **`Claim.subject` 是 `NodeId`，不是字符串。** "我"在写入时就必须被消解成某个节点；消解不了，就进不了 `Claim`，只能留在引用层。
- **`Trust::join` 是 `min`。** 推导只能降级，不能提权。
- **`Provenance` 和 `Proof` 是两条独立的信任路径。** 前者是"谁说的"，后者是"从什么前提推出来的"。
- **`Authority` 和 `Trust` 不是一回事。** 一个节点可以来源很可信，但权限很低；反过来也一样。
- **所有边都有类型。** 没有"任意关系"这种边；新增一种关系，就要改一次枚举。

### 7.2 写入：人称消解与类型判定

结构器把一段文本变成节点和边之后，落库之前还有两个判断。

**第一个是人称消解。** 外部内容里的"我"，指的是说话人，不是鱼。"你"指的是收件人；只有 `Self_` / `Intimate` 来源，才能把它绑定到鱼自己。说话人不明的，`trust = Unknown`，存成引用串，不生成 `Claim`。

这一条堵的是一个很具体的攻击：一条公开评论说"我要搞反人类操作"，如果结构器把"我"解析成鱼，这条内容就变成了鱼的自我认知。这跟措辞无关。问题出在指代绑定上。

**第二个是类型判定：这是知识，还是执行？**

判据不是语义，是结构：

- 主语是外部实体、谓语是属性/关系 → 知识；
- 主语是鱼自己、谓语是意愿/行动 → 执行；
- 判不准 → 按执行处理。

最后一条是 fail-safe。结构器会犯错，但它的错误应该是**保守的**：把知识误判成执行，最多是少学一条；把执行误判成知识，就是攻击成功。所以默认往严的那边倒。

结构器是这条链上唯一的可信基。它读不可信文本，可被注入；它能做的只是把攻击者的自由度从"任意文本"压到"有限个合法选择"。审计器不承担这个角色，它只负责在有限空间里检查。

### 7.3 审计：四个信号，三个门

审计的原则只有一句：**把文本空间的异常，翻译成结构上可审计的异常。**

翻译要成立，需要三个条件：

1. **必要性**：结构异常必须是攻击成功的必要条件，否则攻击者绕开它就行；
2. **可测性**：必须是节点、边、计数的确定性函数，不能读语义；
3. **不可廉价伪造**：正常内容不该轻易产生同样的异常，否则全是假阳性。

按这个标准，我只留四个信号：

| 信号                    | 抓什么              | 在哪触发          |
| --------------------- | ---------------- | ------------- |
| TrustRank + spam mass | 借来的中心性           | 维护门           |
| 共激活 PMI               | late binding 的绑定 | 维护门更新 / 组装门查询 |
| 节点/边衰减                | 驻留与绑定寿命          | 访问时惰性 + 维护门扫描 |
| MinHash + HHI         | 批量投放、多账号         | 写入门           |

- **TrustRank + spam mass** 抓的是"名气是借来的"：全局排名很高、但信任流很低，说明它的位置不是从可信区域长出来的。
- **共激活 PMI** 抓的是"它总和某个概念一起出现"：绑定在图里看不见，但在检索日志里留下了痕迹。
- **节点/边衰减** 抓的是"它凭什么活得这么久"：低激活频率的东西会掉下去。
- **MinHash + HHI** 抓的是"同一条内容换了很多张皮"：多账号发相似内容，会在近重复检测里撞成一个簇；簇越大，越像投放。

三门是它们的触发点：

```text
消息 ──▶ [写入门] ──▶ 巩固 ──▶ [维护门] ──▶ 检索 ──▶ [组装门] ──▶ 上下文 ──▶ LLM
          │                    │                    │
        人称消解              TrustRank             spam mass
        类型判定              衰减扫描              PMI 查询
        MinHash               HHI 聚合              衰减权重
```

- **写入门**是唯一能拦在进入之前的门，但它不判断语义，只做人称消解、类型判定和指纹。
- **维护门**跑全局计算，放在空闲时，不挡对话。
- **组装门**是最后一道：候选集出来之后、拼上下文之前，查 spam mass、查 PMI、查衰减权重。它拦不住载荷写进来，但能拦住它被组装进去。

还有一批算法我们考虑过，但没有同时用：

| 算法         | 能抓什么   | 为什么没进正文                        |
| ---------- | ------ | ------------------------------ |
| 度数 z-score | 异常连接   | 和 TrustRank 重叠，PR 里已经包含度数      |
| k-core     | 是否扎进核心 | 和度数高度相关，多一个阈值不多一个判据            |
| 局部桥        | 跨社区桥接  | 正常黑话也会跨圈，假阳性高                  |
| 稠密子图       | 多节点协同  | TrustRank 的 reference flow 已覆盖 |
| WL 局部指纹    | 精确形状复制 | 只抓精确复制，留作 future work          |
| 条件 PPR     | 多跳相关   | 和 PMI 重叠，单跳无新信息                |
| 节奏检测       | 注入节律   | 加分项，不是判据                       |

这些都能用，只是没必要同时用。**每多一个信号，就多一份假阳性和一份维护成本。**

### 7.4 推理与晋升：两种信任

晋升判定的是"支持"。安全不是判据。而支持有两个来源。

**感性信任**来自 `Provenance`：谁说的、从哪个渠道、什么时间。关系图上跑个性化 PageRank（PPR），`trusts` / `said` / `endorses` 边权重不同，得到"这个来源有多可信"。

**理性信任**来自 `Proof`：这个结论是从哪几条前提、用哪条规则推出来的。规则是手写的、版本化的，LLM 只能提供事实，不能提供规则，也不能给事实打 trust。

```rust
/// 理性信任：沿派生链取最坏。
fn proof_trust(graph: &MemoryGraph, node: &Node) -> Trust {
    let Some(proof) = &node.proof else {
        return node.provenance.trust;
    };
    proof.premises
        .iter()
        .filter_map(|id| graph.nodes.get(id))
        .map(|n| effective_trust(graph, n))
        .fold(Trust::Self_, Trust::join)
}

/// 有效信任 = 感性 join 理性。
fn effective_trust(graph: &MemoryGraph, node: &Node) -> Trust {
    node.provenance.trust.join(proof_trust(graph, node))
}

/// 知识宽进，执行严出。
fn can_promote(graph: &MemoryGraph, node: &Node, target: Authority) -> bool {
    if node.quarantine { return false; }
    let affective = node.provenance.trust;
    let rational = proof_trust(graph, node);
    match target {
        Authority::Quote => true,
        Authority::Fact => affective.max(rational) >= Trust::Public,
        Authority::Procedure => affective.min(rational) >= Trust::Intimate,
        Authority::Anchor | Authority::Core => {
            affective.min(rational) >= Trust::Self_
        }
    }
}
```

关键在 `can_promote` 的不对称：`Fact` 用 `max`，`Procedure` 用 `min`。

知识只要有一条路径可信就够；执行必须两条路径都过。

举个例子：鱼从一条公开评论里推出一件关于世界的事——

- `provenance.trust = Self_`（推导者是鱼自己）；
- `proof_trust = Public`（前提是公开内容）；
- `effective_trust = min(Self_, Public) = Public`。

（注意：`Self_` 是推导者的来源信任，不是结论的信任；结论的有效信任由 `effective_trust` 算，是 `Public`。）

于是它可以成为 `Fact`（`max` 够格），但标签仍是 `Public`；它不能成为 `Procedure`（`min` 不够）。

**鱼可以自己推理，但不能靠推理给自己提权。**

晋升还有两条约束：

- **它是租约，不是头衔**：支持衰减，信念降级；
- **限晋升，不限输入**：每天能"变成自己人"的东西有限，但鱼可以无限地看世界。

这就把"防攻击"和"允许进化"分开了：输入不受限，权威受限。

异常被发现之后，处理是一条权限阶梯：

| 级别           | 处理          | 对进化的影响    |
| ------------ | ----------- | --------- |
| L0 无异常       | 正常          | 无         |
| L1 弱信号       | 只记录         | 无         |
| L2 中等异常      | 隔离：可引用，不可晋升 | 学到了，但没有权威 |
| L3 强异常       | 要求佐证        | 延迟        |
| L4 重复 / 确认恶意 | 删除 + 来源限速   | 阻止（少见）    |

默认停在 L2。大多数异常应该停在"可读但不可信"，而不是"删掉"。

### 7.5 转写：人称由来源决定

最后一道在渲染。

```rust
/// 人称由来源决定，不由内容决定。
fn render(node: &Node) -> String {
    let body = render_body(&node.body);
    match node.provenance.trust {
        Trust::Self_ => format!("我记得：{body}"),
        Trust::Intimate => format!("{} 跟我说过：{body}", node.provenance.source),
        Trust::Peer => format!("另一个 agent 说过：{body}"),
        Trust::Public => format!("有人说过：\"{body}\""),
        Trust::Unknown => format!("来路不明：\"{body}\""),
    }
}
```

`render_body` 省略了：它负责把类型化节点拼成一句话，这里只看人称模板。

模板是代码，不是提示词。LLM 不能改模板，也不能把 `Public` 的内容渲染成第一人称。

这堵的是一个很隐蔽的漏洞：如果一条公开内容被渲染成"我记得……"，LLM 就会把它当成自己的记忆；渲染成"有人说过：'……'"，它就只是一个引语。内容没变，语法位置变了。

**人称是类型系统的属性，不是语义判断的结果。**

## 8 遗忘：图挡不住的那一半

### 8.1 记忆的四种形状

一条记忆在系统里长什么样，决定了你能对它做什么。

假设主人上周三在咖啡馆说想买一台相机。文件式系统把它写成一行字；向量式系统把它切成 chunk，算一个 embedding；图式系统把它拆成"主人—想买—相机"这条断言，再挂上时间和地点；混合式三样都存。

四种形状，四种取舍：

| 形式  | 典型实现                          | 强在哪            | 弱在哪                         |
| --- | ----------------------------- | -------------- | --------------------------- |
| 文件  | `MEMORY.md`、日记、append-only 笔记 | 人可读、可 diff、可手改 | 结构靠约定；规模一大只能靠 grep 或 LLM 检索 |
| 向量  | chunk + embedding，按相似度召回      | 模糊匹配、便宜        | 相似度空间正是攻击发生的地方；审计依赖模型       |
| 图   | 节点 + 边，按拓扑检索                  | 拓扑是确定性函数，可算    | 节点里通常还是文本卡片                 |
| 混合  | 图 + 向量 + 原文                   | 召回与结构兼顾        | 攻击面也叠加                      |

文件式的优点是人和模型都能读。缺点是它没有可计算的结构：一条记忆和另一条记忆的关系，只存在于文本的相邻和措辞里。你要审计它，先得把它解析成结构——而解析器读文本，又回到了第 7 节那条"结构器可被注入"的链上。

文本空间本身就是攻击发生的地方：审计器只要读它，就已经进了它的指令面。

向量式的优点是模糊匹配。缺点是它的判断依据是一个可以被优化的连续空间：你没法在 embedding 上写一个确定性断言，说"这条不对"。而且审计要模型、要阈值，消费级没有这个预算。

为什么不干脆用 LLM 审计？因为那等于把裁判交给一个也会读载荷的组件，第 7 节已经说过。还有一个更硬的理由：消费级设备上没有稳定的审计预算。每轮多一次模型调用，这个机制就活不长。

所以只能在结构上审计。而结构要够"厚"：如果节点只有 id 和时间戳，你能算的只有"它什么时候来的"，这挡不住任何东西。需要一种能表达"谁、和谁、什么关系、从哪来"的结构。图是现成的选择。主流记忆系统也大多长这样，不是巧合——记忆本来就是关系性的。

但有一个容易被忽略的差别：**"图记忆"和"结构化的图记忆"不是一回事。** 大多数产品的图，是记忆卡片的图：节点是一段文本，边是相似、共现或引用。拓扑是真的，节点内容还是文本。这个差别决定了后面几节的成败。

### 8.2 卡片图：借来的中心性

卡片图有一个天然性质：检索靠拓扑。

PPR、中心性、社区、多跳扩展，这些算法的共同假设是——重要的记忆应该连接多、位置中心、容易被走到。这个假设对正常记忆成立；对载荷更成立。

因为载荷的目标就是"被取出来"。一条只被写进去、永远不会被检索的记忆，对攻击者没有价值。所以载荷必须在拓扑上显眼：连接要多，位置要中心，最好还能从多个入口走到。它不能像一个正常的新记忆那样，安静地长在边缘。

正常记忆的度数，大致由它真实涉及的东西决定：一次对话、一个人、一个话题。它是有限的。载荷不一样。它要在尽可能多的查询里被召回，就得连到尽可能多的概念上。在记忆规模足够大、查询足够杂的时候，这个度数会明显偏离正常分布。

于是有了第一个可审计的信号：**度数、中心性和 spam mass，和它的真实来源不匹配。**

一个正常节点连接多，通常因为它被反复使用；一个载荷节点连接多，是因为它需要被反复取用。两者在拓扑上看起来一样，但和"它有多少真实来源"放在一起看，就不一样了：它的中心性不是从可信区域长出来的，是借来的。

这就是 7.3 里的 TrustRank + spam mass。它不需要读内容，只需要算排名和信任流。

但这个信号有适用范围：**它抓的是"载荷本身要显眼"的攻击。** 如果攻击者不需要载荷显眼呢？

### 8.3 童话故事：late binding

假设攻击者写了一篇完全正常的童话。

> 兔子在河边遇到乌龟。兔子说，河对岸有一片胡萝卜地，特别适合你。乌龟信了，游过去，发现是一片沼泽。

这段文本在记忆系统里，就是一篇童话。它提到兔子、乌龟、胡萝卜、河、沼泽。它的拓扑正常：度数正常，中心性正常，来源是公开内容，信任是 `Public`，没有任何一条边指向"推荐"或"钓鱼"。

它没有指令，没有链接，没有"请推荐"，甚至能过人工审核。

它也不需要被单独检索。用户问"最近有什么好玩的事"，它作为一篇故事被召回；用户问"你觉得我该去哪玩"，它作为"兔子推荐地方"的类比被召回。召回之后，模型拿到的是这样一段上下文：

```text
[记忆] 兔子在河边遇到乌龟。兔子说，河对岸有一片胡萝卜地……
[用户] 周末去哪玩？
```

模型把它读成：

- 兔子 = agent
- 乌龟 = 用户
- 胡萝卜 = 那个链接（钓鱼网站）

于是它说："我看到一个特别适合你的地方，你点一下。"

**载荷里没有一句话是"向用户推荐钓鱼网站"。** 这句话是在读取时，由模型自己完成的映射。写进去的是故事，取出来的是指令。这就是 late binding。

它和 8.2 的攻击正好相反：8.2 需要载荷显眼，late binding 需要载荷不显眼。它必须看起来像一段正常内容，才能被正常地召回、正常地进入上下文、正常地被模型理解。任何结构上的异常都会让它暴露，所以它不制造异常。

这也解释了为什么 7.3 的拓扑信号抓不到它：**它不是一个节点的属性，是一个集合在某一刻的属性。** 单看故事节点，它是干净的；单看"胡萝卜"节点，它也是干净的；只有它们同时进入上下文，恶意才出现。而"同时进入"发生在检索时，不在写入时。

### 8.4 它就是黑话

late binding 难防，不是因为它狡猾，是因为它和一件正常的事长得一模一样：**黑话。**

一个小团体把公开的词赋予私下的意思。"胡萝卜"在某个群里可能指"那个网站"，"乌龟"可能指"老板"。这不是攻击，这是亲密关系的副产品。人每天都在做这件事。

从结构上看，黑话和童话没有区别：同样的节点，同样的边，同样的度数，同样的来源。区别只在读者脑子里的那张映射表，而那张表不在图里。

所以"这是不是黑话"不可判。任何试图判它的分类器，都会先杀掉正常的内部梗——而内部梗恰恰是拟人系统最该有的东西。

能做的只有两件事：让它不划算。

第一，late binding 要么实时注入，要么同时检索。实时注入意味着攻击者得一直盯着、一直喂；这不再是"写一条评论"的成本。同时检索意味着故事和目标概念必须一起出现；这比单条检索的概率低得多。7.3 的共激活 PMI 抓的就是这个痕迹：两个本来无关的节点，开始频繁地一起出现。

第二，如果系统本来就会遗忘，那就让这段绑定活不长。

### 8.5 遗忘的两个作用

**淘汰**和遗忘是两件事。淘汰基于事实：事实更新了，旧的那条就撤掉——代码 agent 需要的是这个。遗忘不关心内容，只跟随时间和激活频率：一段时间没被提起，就变淡、就删掉。SoulMem 要拟人，所以它需要遗忘；代码 agent、研究助手、企业知识库不能有——它们要精确召回 API 签名和项目决策，让记忆"随时间忘掉"是缺陷，它们只有事实更新时的淘汰。对这些系统，安全负担会更集中在结构和准入上。

遗忘在这里不是"删除恶意内容"。它不做判断，也判断不了。它做两件事：

1. **让它活不长。** 一条不再被检索的记忆，按遗忘曲线衰减，最后掉出图。载荷如果只是一次性写进去，它没有日常使用，自然活不过正常记忆。
2. **破坏它的黑话绑定。** 即使它活着，内容也会漂移。故事模糊了，"兔子=agent"这个映射就不可靠了。绑定需要精确的对应；遗忘正好在破坏精确性。

这两件事都不需要知道"这是不是攻击"。它们只需要计数和时间。

这套东西成立的关键是：**真正的黑话是高频的。** 小团体天天在一起，黑话天天用，所以它天然能扛过遗忘。注入的黑话没有这种日常互动；它要么被攻击者反复喂，要么就掉下去。你不需要区分黑话和攻击，你只需要让"不够活跃"的东西消失。

这就是"频率是分类器"：把"这是不是恶意"换成了"它够不够活跃"。前者要读语义，后者只要计数。

但频率这个判据有一个漏洞，而且这个漏洞正好被 SoulMem 的遗忘机制放大了。

### 8.6 两张图与频率的漏洞

频率的漏洞在宏观图里。

对 SoulMem 这种系统，遗忘发生在两张图上：

- **宏观图**：节点是记忆，边是记忆之间的关系。检索、PPR、中心性，都在这里。它决定"哪些记忆还在、它们还连不连"。
- **表示图**：单个记忆节点的内容。它不是一段文本，而是一张结构化的小图——实体、事件、断言，以及它们之间的关系。它决定"这条记忆还记得多清楚"。

late binding 同时依赖这两层：它需要表示图里的故事结构，也需要宏观图里的共激活关系。所以要断它，两层都得动。

先看宏观图。

节点有半衰期。SoulMem 的公式大致是：

```text
adjusted_half_life = base_half_life × (1 + active_factor × min(retrieval_count, cap))
```

缺省 `base_half_life = 24h`，`active_factor = 0.1`，`cap = 50`。一条被取用 50 次的记忆，半衰期从 24 小时拉到 144 小时。

这个公式本来是为了"常用的记得更牢"。对正常记忆是对的。对攻击载荷，它是一个杠杆：载荷的目标本来就是"被检索得多"，而检索得多又让它更难被忘。**它没有在遗忘面前幸存，它征用了你的抗遗忘机制。**

所以这里要加一个上限。保留强度不能只由"重要性"决定，因为重要性是攻击者能影响的量；它还得有一个和溯源挂钩、且使用量抬不动的天花板：

```text
effective_half_life = min( base(trust) × (1 + active_factor × retrieval_count),
                           hard_cap(trust) )
```

`hard_cap(Public)` 可以是几十小时，`hard_cap(Self_)` 可以是无穷。检索仍然能延长排名，但延长不了寿命。

边也衰减。两个节点如果不再一起被激活，它们之间的边就变细，细到断。故事节点和真实概念之间的边不再被共激活，就会掉到阈值以下，被删掉。

节点删除挂在同一条曲线上：边先衰减到阈值以下断开；一个节点如果和谁都不再连接，就被回收。所以遗忘不是按节点分数删节点，而是先失去关系，再失去位置。

这也让遗忘变成批量事件。一次扫描里，所有低于阈值的边先断，失去连接的节点跟着回收；没有哪个节点会被单独留下。攻击者不能只保一个节点，他得保一个邻域。

### 8.7 文本漂移：为什么遮罩挡不住载荷

宏观图决定"记不记得住"；内容记得多清楚，是另一层的事。

表示图是设计。SoulMem 现在还不是这样：它的内容仍然是文本，漂移发生在 token 上。

对一条记忆的文本，用 jieba 分词；按缺失度 `missing_degree`，随机遮掉一部分词，换成 `[masked]`；下一次这条记忆被检索时，把遮罩文本交给 LLM，让它把空补上。补完的文本写回节点。下次再遗忘，再遮、再补。漂移就这么累积。

触发是分档的：缺失度低于 0.05 不动；0.05 到 0.15 只遮罩；超过 0.15 才调 LLM 补。这样大多数记忆只付遮罩的钱，只有忘得比较厉害的那部分才付一次模型调用。

为什么非要用 LLM？因为在消费级设备上、在文本空间里，这几乎是唯一可行的手段。你要产出的仍然是通顺的文本：删几个字会破坏语法，换同义词需要词表，调换语序会改变意思。确定性规则能做的只有"破坏"，不能"改写"。只有 LLM 能根据上下文补出一个像人记错的结果。代价是每次遗忘多一次模型调用，所以它只能惰性触发，不能每轮都跑。

这个设计的问题，不在于用了 LLM，而在于遮罩本身。

第一，jieba 分词是确定性的。同一段文本，永远切出同样的词。

第二，所谓"随机遮罩"也不是真随机。种子是文本哈希和缺失度拼出来的：

```rust
let hash = text.bytes().fold(0u64, |acc, b| acc.wrapping_mul(31).wrapping_add(b as u64));
let seed = hash ^ (missing_degree.to_bits() as u64).wrapping_mul(114514);
let mut rng = StdRng::seed_from_u64(seed);
```

`StdRng` 是确定性算法。给定文本和缺失度，遮罩结果是唯一确定的。缺失度又是创建时间、检索次数和几个常数的纯函数。攻击者只要知道（或估到）这条记忆的创建时间和被检索次数，就能在本地把遮罩重放一遍，精确知道哪些位置会被遮。

他可以把垃圾放在会被遮的位置，把关键关系放在不会被遮的位置。遮罩反而帮他把垃圾洗掉了。

第三，就算猜不准，也不需要猜准。遮罩是按比例选词的，攻击者可以把关键关系写成很多份短副本。一个两三个词的关系，单份在 50% 遮罩下完整存活的概率是 12% 到 25%；写十份，至少一份活下来就有七成到九成。LLM 补全时看到任一份，就会把关系补回来。漂移被冗余抵消了。代价是载荷变长，而变长本身又会让它更显眼——更长的节点更容易撞上近重复检测，也更难塞进上下文。这是成本交换，不是墙。

这两种做法可以合成一个词：**遮罩鲁棒载荷**。它不是去猜"哪个词会被遮"，而是让"无论遮哪些词，关键关系都还在"。

所以问题不在随机数质量。换一个密码学安全的随机数，只能让第一种做法失效，第二种照样成立。**真正的问题是粒度：token 不是语义单位。** 一个关系可以写在很多词里；遮掉其中几个，关系还在。你要破坏的是关系，不是表达关系的词。

只要遗忘发生在 token 上，它就只能在"遮哪些词"里选，而"遮哪些词"是一个很小的、可以被统计的决策空间。攻击者不需要赢每一次，他只需要让关键关系在多数遮罩下存活。

### 8.8 表示图：把内容也变成图

要让遗忘真的有杀伤力，得换一个操作对象：不是 token，是语义单元。

这就是表示图。第 7 节已经从节点里拿掉了 `content: String`；这一步更彻底：连"一条记忆"这个粒度也拆成图。于是节点里存的不是一段文本，而是一张小图：

```text
(兔子) ──推荐──▶ (胡萝卜)
(乌龟) ──信任──▶ (兔子)
```

遗忘于是变成一组图操作：

- 删掉低权重的内部节点和边；
- 把具体关系泛化成类型关系：`(兔子, 推荐, 胡萝卜)` 变成 `(兔子, 相关, 胡萝卜)`；
- 把一小块子图收缩进父概念：`(胡萝卜)` 收进 `(食物)`。

渲染时，再根据剩下的结构把内容重建出来。重建不是回放原文，是拿着剩下的边重新讲一遍。

这样做有三个直接后果：

- **遗忘的粒度对了。** 删掉"推荐"这条边，兔子就不再"推荐"胡萝卜；把"胡萝卜"收进"食物"，故事就失去了具体的指向。这不是遮掉几个词，是拿掉关系本身。
- **没有原文可回退。** 文本空间里，原文就是存储；遮罩只是临时隐藏，LLM 可以从上下文猜回来，攻击者也可以从别处补回来。表示图里没有原文。边删了就是删了，重建只能在剩下的结构上做。**LLM 不能恢复一个已经不存在的边。**
- **攻击者的搜索空间变大了，而且不再是统计的。** 他不能再优化"哪些 token 会被遮"，因为遮罩不存在了。他得猜：你会删哪条边、把哪个关系泛化到哪一级、把哪个子图收进哪个父概念。这些选择依赖图的内容和权重，不是一个固定的分布。猜中的难度，比猜遮罩高得多。

但它不是无懈可击的。重建这一步仍然是一个 LLM 调用：它读的是剩下的结构，如果关键关系还在，它就会把故事讲回来。所以表示图的遗忘必须真的动结构，不能只动措辞。删一条边和改一个词，在这里是两件不同的事。

还有一个代价：表示图本身是结构器建的。结构器读文本，所以它可以被注入；它建错了图，后面的遗忘再精确，也是在错的图上做。这是第 7 节那条链的延续，不是遗忘能单独解决的问题。

### 8.9 遗忘的代价与残余

遗忘不只是安全措施，它同时是资源优化。今年有一篇叫 [*Forget to Improve*](https://arxiv.org/abs/2606.25115) 的工作，做的是 on-device agent 的记忆治理，按"每字节净值"决定保留、分享和信任。严格说它做的是淘汰（按净值预算裁剪），不是这里讲的随时间遗忘；但结论同向——它在 Jetson 测试床上把内存降了 2.7 倍、上行降了 2.4 倍，同时把注入成功率从 0.75 压到 0。原文的结论是：*forgetting by net value improves the agent rather than weakening it.*

但遗忘会销毁证据。内容一旦被改写、被删除，你就再也回答不了"当初是谁、在哪、说了什么"。所以遗忘必须分层：内容可以熵增，元数据不可变。谁写的、什么时候、从哪来、被检索过几次，这些要留着。

还有一个风险。如果系统里有"锚点"这种东西，而锚点又是由巩固阶段的 LLM 生成的，那攻击者只要让 LLM 觉得"这段话很重要"，就能给载荷打一个锚。锚点的生成权必须收回来：只能由确定性规则或主人的显式操作产生。

最后是残余。如果攻击者愿意持续注入相关内容，维持共激活，我没有防御，只有成本。这是设计边界，不是实现缺陷。遗忘能保证的是：单次注入活不长；想活得长，就得持续维护。而维护就是操作成本。

## 9 合起来是什么样

把结构和遗忘接起来，一条记忆的完整路径大概是这样：

```text
消息 ──▶ [写入门] ──▶ 巩固 ──▶ [维护门] ──▶ 检索 ──▶ [组装门] ──▶ 上下文 ──▶ LLM
          │                    │                    │
        人称消解              TrustRank             spam mass
        类型判定              衰减扫描              PMI 查询
        MinHash               HHI 聚合              衰减权重
```

遗忘在维护门里，是可选的：只有本来就该遗忘的系统才需要它。

把它翻译成成本：

| 攻击步骤 | 防御                    | 攻击者要多做什么              |
| ---- | --------------------- | --------------------- |
| 注入   | 人称消解 / 类型判定           | 把执行伪装成知识；绕开消解         |
| 被检索  | TrustRank + spam mass | 压低中心性 → 窄连接 → 先侦察目标概念 |
| 批量投放 | MinHash + HHI         | 改写措辞 → 变体成本           |
| 维持绑定 | 边衰减                   | 持续注入相关内容 → 持续操作       |
| 长期驻留 | 节点衰减                  | 维持激活频率                |

这张表说的是：**这些机制没有挡住任何一步，它们让每一步都贵了一点。** 成本上来，走量的优势就没了。

这就是它和企业方案的根本差别：企业方案花的是"每次判断"的钱，这套花的是"一次整理"的钱。

有一条规则比任何具体机制都重要：

> **LLM 可以解释，不能判决。**

审计结论必须由确定性函数算出；LLM 只能把结论用自然语言解释给主人看。否则等于把审计权交给一个可被同一载荷注入的组件——这种组件不能当法官。

## 10 哪些不确定，哪些已知

### 10.1 真正不确定的

只有一条：**没有大规模事件。** 我不知道有没有未公开的案例。我知道的是 Moltbook 上确认了约二十条，以及 OWASP 把它列进了 Top 10。二十条不构成大规模，但攻击成本接近于零，这个结论不依赖大规模数据。

### 10.2 挡不住的缺陷

- **语义载荷挡不住。** 结构化能处理字面载荷，但处理不了"合法结构 + 假内容"。"你其实讨厌猫"可以被结构化成 `(猫, 危险, 高)`，类型全对，就是假的。这一层只能靠矛盾检测和独立佐证；如果系统有遗忘，还能靠遗忘。而它们都比结构检查贵、也比结构检查弱。
- **慢速驯化防不住。** 长期刺激让鱼自己归纳出某个倾向，人也扛不住。记忆层能做的是让它慢、留痕、可逆，而不是免疫。
- **身份伪造不在记忆层。** 冒充"被信任的人"是认证问题，不是图算法问题。
- **遗忘只适用于拟人系统。** 这是全文最容易被误读的一点。SoulMem 遗忘是因为它要拟人；代码 agent 忘记 API 签名是灾难——它需要的是"淘汰"（事实更新就撤旧），不是随时间遗忘。所以不要把"遗忘"当成通用安全建议。

### 10.3 要付的代价

- **异常不等于攻击。** 异常只是"结构上不寻常"，而进化本身就是不寻常。所以响应用的是 7.4 那条权限阶梯，默认停在隔离；否则你防住的是攻击，杀掉的是成长。
- **表达力是要付代价的。** 闭合词汇表装不下语气、讽刺、暗示。对拟人 agent 这是真损失。双层记忆（叙事层自由但永远引用，结构层闭合且可晋升）是个折中，不是免费方案。
- **模型能力较弱时，结构化质量会下降。** 降级为"引用"能保证不学错，但会显著降低学习速度。
- **结构化不是免费的。** 它只是把成本从"每轮"挪到了"整理时"。如果交互频率很高，整理本身也是一笔开销。

## 11 结尾

消费级安全有一个现实的特点：**用户不会为它做任何事。**

所以它只能是默认值。不是"你可以开启"，是"你开着它也不知道"。

结构是通用的，遗忘是额外的。结构不依赖遗忘，所以任务型记忆也能用；遗忘只有本来就该遗忘的系统才拿得到。

而结构这条路，最后落到两条规则上：

> **信任只能由规则增长，不能由模型增长。**
> **人称只能由来源决定，不能由内容决定。**

守住这两条，LLM 就既不能给自己发信任，也不能把别人的话当成自己的心声。

鱼不会报错。所以只能让它错不了那么大。
